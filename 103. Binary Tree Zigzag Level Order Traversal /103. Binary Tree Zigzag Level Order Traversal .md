- 何も見ずに解く
  ```py
  # Definition for a binary tree node.
  # class TreeNode:
  #     def __init__(self, val=0, left=None, right=None):
  #         self.val = val
  #         self.left = left
  #         self.right = right
  class Solution:
      def zigzagLevelOrder(self, root: Optional[TreeNode]) -> List[List[int]]:
          result = []
          if root is None:
              return result

          def zigzag_level_order(node: TreeNode, level: int, switch_flg: bool):
              while level >= len(result):
                  result.append([])
  
              if switch_flg:
                  result[level].insert(0, node.val)
              else:    
                  result[level].append(node.val)
  
              if node.left is not None:
                  zigzag_level_order(node.left, level + 1, not switch_flg)
              if node.right is not None:
                  zigzag_level_order(node.right, level + 1, not switch_flg)
              
          zigzag_level_order(root, 0, False)

          return result 
    ```
- ベースは、[102. Binary Tree Level Order Traversal](https://leetcode.com/problems/binary-tree-level-order-traversal)の実装
- bool値のフラグによって、配列の末尾に要素(node.val)を追加するか、先頭に追加するかを切り替える

- もし親の処理部分(一部分)を実施する関数内で要素の入れ替えを実施しつつ処理を進めていければ、計算量の低減および可読性の向上が見込めるのではないか
- 上記実装案を考えたものの、ある階層の要素を追加する中で並べ替えを行おうとした場合、予期せぬ並び順になってしまう懸念があり、その階層の要素の追加が完了したことを以て並べ替えを実施するのが一番シンプルそう

```python
class Solution:
    def zigzagLevelOrder(self, root: Optional[TreeNode]) -> List[List[int]]:

        result = []
        if root is None:
            return result

        def build_zig_zag_level_elements(node: TreeNode, pos: int, odd_level: bool):
            while pos >= len(result):
                result.append(deque())
            
            if odd_level:
                result[pos].appendleft(node.val)
            else:
                result[pos].append(node.val)

            if node.left is not None:
                build_zig_zag_level_elements(node.left, pos + 1, not odd_level)
            if node.right is not None:
                build_zig_zag_level_elements(node.right, pos + 1, not odd_level)
  
        build_zig_zag_level_elements(root, 0, False)
        return [list(deq) for deq in result]
```
- 「deque を使い、最後に list に変換する」方法のRuntimeでは3msと、「append() のみ行い、最後に逆順にする」方のRuntimeの0msより遅かった。メモリも19.49MBと19.37MBだったのでほぼ変わらない。
