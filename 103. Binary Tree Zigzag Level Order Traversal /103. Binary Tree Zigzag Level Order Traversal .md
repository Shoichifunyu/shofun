  ```py
  # Definition for a binary tree node.
  # class TreeNode:
  #     def __init__(self, val=0, left=None, right=None):
  #         self.val = val
  #         self.left = left
  #         self.right = right
  class Solution:
      def zigzagLevelOrder(self, root: Optional[TreeNode]) -> List[List[int]]:
          result = []
          if root is None:
              return result

          def zigzag_level_order(node: TreeNode, level: int, switch_flg: bool):
              while level >= len(result):
                  result.append([])
  
              if switch_flg:
                  result[level].insert(0, node.val)
              else:    
                  result[level].append(node.val)
  
              if node.left is not None:
                  zigzag_level_order(node.left, level + 1, not switch_flg)
              if node.right is not None:
                  zigzag_level_order(node.right, level + 1, not switch_flg)
              
          zigzag_level_order(root, 0, False)

          return result 
    ```
- ベースは、[102. Binary Tree Level Order Traversal](https://leetcode.com/problems/binary-tree-level-order-traversal)の実装
- bool値のフラグによって、配列の末尾に要素(node.val)を追加するか、先頭に追加するかを切り替える

- 1つの階層がすべて揃った後に、フラグによって要素の並び順を逆にするかを決める方法
- この場合の方がinsertを使わない分、計算量が抑えられる
- 子要素も同様の処理を行うため、親と子の要素を返す関数を別途切り出す必要がある(ループで親要素でやっていた処理を子にも行う)
- (ある階層で)すべての要素が揃うまでには、呼び出し元でその階層の処理それ以上ないことを担保する必要がある。親から子を呼び出す処理と親自身の処理結果という2つの返り値を以て、その階層(親の階層)の処理の完了を担保する
- もし親の処理部分(一部分)を実施する関数内で要素の入れ替えを実施しつつ処理を進めていければ、計算量の低減および可読性の向上が見込めるのではないか
- 上記実装案を考えたものの、ある階層の要素を追加する中で並べ替えを行おうとした場合、予期せぬ並び順になってしまう懸念があり、その階層の要素の追加が完了したことを以て並べ替えを実施するのが一番シンプルそう
